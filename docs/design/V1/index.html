Design system

Every part below is drawn from src/styles/tokens.css; the rules are in docs/design/DESIGN.md.

DS1 Colour

Tokens
  • Charcoal surfaces with a faint cool hint (P22), one cobalt accent. Cards separate from the background by a tone step, not an outline (P28).
  • Every text colour passes 4.5 : 1 on bg, surface, raised and fill; input borders and focus pass 3 : 1.

App shell

Top bar and a side menu on the phone, a permanent side menu from 960 px (N1b, P7, P8).

N1b Side menu open

Sprint 0
  • The menu slides in from the left over a dark scrim; it closes on a tap outside, a swipe left, Escape or after choosing an item.
  • More destinations arrive with later epics; the menu grows downward, version stays at the bottom.

Sign in

Email and password, no sign-up anywhere (A1). Sign in again after 30 days (A3).

A1 Sign in

Sprint 0
  • Fields support the password manager (autocomplete email / current-password). Show toggles the password; there is no confirm field.
  • Desktop: the same column, centred on a card, without the side menu.

A2 Sign in, error

Sprint 0
  • One message for a wrong email or password, above the form and announced to screen readers. The password is cleared and focused, the email stays.

A3 Forgot password

Sprint 0

A4 Reset link sent

Sprint 0
  • Neutral wording: it does not reveal whether the address has an account. Resend is disabled for 60 seconds.

A5 Choose a new password

Sprint 0
  • Opened from the email link (Supabase default flow). An expired or used link shows the message on the right.

Import

Pick the file on the phone, drop it on desktop. Every activity is stored, only rides are shown (P13); broken activities are skipped and listed (P14).

C1 Choose file

Sprint 1
  • The whole card is the target: a tap opens the file picker. On desktop the file can be dropped anywhere on the page (X2).

X2 Import on desktop, dragging a file over

Sprint 1
  • Drag-over: accent-tinted fill and a 2 px accent edge; no glow.

C2 Checking and saving

Sprint 1
  • Step 1 checks the whole file, step 2 saves in one database call. A five-activity file finishes in about a second, so this mainly shows for the backfill.

C3 Import summary

Sprint 1
  • Outcome titles name what the number is (P17); the six numbers add up to the activities in the file. New rides is the one tinted card. Numbers count up once (off with reduce motion).
  • Skipped activities are listed with their position in the file and the reason; the rest is saved (P14).

C4 File can't be imported

Sprint 1
  • Only for a file that is not a valid export at all (not JSON, wrong structure, unsupported version). Nothing is saved.

C5 Import history

Sprint 1
  • Newest first, reached from Last import on C1. On desktop a table with one column per outcome; zeros are muted.
  • A file that is not a valid export also appears, as "Not imported" with the reason (decided, D-PO4).

Settings, What's new, What's next

Theme switch with System as default (P9); release notes with Feature, Fix and Technical labels (P18).

G1 Settings

Sprint 1
  • Units and time zone are information only. Sign out sits with the account and needs no confirmation.

G2 What's new

Sprint 1
  • The version you have not seen yet is marked New; opening this page or dismissing the bottom card marks it as seen on every device.

G3 What's next

Sprint 1
  • Only version, title, sprint, status and tagline (P18), read from the backlog at build time.

Rides

Cards on the phone, a dense table on desktop (P10); week or month with totals, commutes can be hidden (P11). Power and heart rate show a dash when missing.

B1a Rides, week view

Sprint 2
  • Six metrics in two rows, fixed order and colours. Ride tags (Road, MTB, Commute, Indoor) are plain text in the meta line (P24).
  • Bottom card after an update (B1d): the list keeps bottom padding the height of the card, so no ride stays hidden.

B1a-month Rides, month view with commutes hidden

Sprint 2
  • Hide commutes is remembered on the device. Totals follow the filter.

X1 Rides on desktop

Sprint 2
  • Sortable and filterable (D-PO6). Default: newest first, grouped by week or month with totals. Rows open the ride (B4); hover is a tone step, keyboard focus a 2 px ring.
  • Every column header is a 44 px button with aria-sort on the header cell. The arrow shows on the sorted column only (and on hover). Numbers sort highest first, Name A to Z; a second click reverses.
  • Sorting by any column other than Date shows one flat list without week rows; Week / Month comes back when you sort by Date again. The line above the table gives the count and totals of what is shown.
  • Filters: search by name, Type (All types, Road, Gravel, MTB, E-bike, Indoor, Commute), Period (All time, Last 4 weeks, Last 3 months, This year, a year, Custom range with From and To fields) and Hide commutes. Clear filters appears once a filter is on. No matches: "No rides match these filters." with Clear filters.
  • Phone keeps Week / Month and Hide commutes (B1a); no sort or filter on the phone for now.

B2 Rides, empty

Sprint 2
  • Import rides opens the Import page (C1). How do I get the file opens a short help sheet.

B3a Rides, loading

Sprint 2
  • Skeleton cards in the fill tone with a slow pulse (static with reduce motion); never a spinner-only screen.

B3b Rides, error

Sprint 2
  • The error is a bottom card like the update card (P12) with Try again. No offline mode.

B4 Ride detail, first version

Sprint 2
  • Distance is the one large number; the other five metrics follow in the fixed order.
  • Route shape only (D-PO5): the ride's polyline drawn as one accent line on a plain card, with a start dot.
  • Delete ride is a calm destructive button that asks to confirm; a deleted ride is skipped on later imports (P15). Weather is parked (P19).

Background

The gradient splash is the background (D-PO1, Q4 closed).

BG1 Background: splash

Decided
  • Three soft colour fields on the screen root only (P25); cards stay opaque. Flow lines are dropped.
  • Flat (data-background="flat") is only a technical fallback, not a choice in Settings.
