Every field beyond distance/time/elevation is optional per ride.       | 15 Oct 2026. | P6  | Units and locale      | **English UI, metric units (km, km/h, W, bpm), Europe/Brussels time zone, light/dark mode following the system.**                                                                              | 15 Oct 2026.                                                                                                                                     |

Migrations in `supabase/migrations` via the Supabase CLI; no manual schema changes.                                                         | Custom server only if a later sprint needs one (e.g. an Edge Function).                                                    |
| T3  | Environments     | **Two free Supabase projects: `cycling-hub-dev` (dev + previews) and `cycling-hub-prod` (production).**                                                                         | 15 Oct 2026. Supabase branching rejected: needs the Pro plan and adds moving parts. Known cost: free projects pause after ~7 days idle. |
| T4  | Hosting          | **Vercel**: production from `main` only, previews for `dev` and every other branch.                                                                                            | Kickoff brief.                                                                                                             |
| T5  | Ride timestamps  | **`startDateLocal` is read as Brussels wall-clock time**; its trailing `Z` is wrong (the value is local, not UTC), and `startEpoch` has the same offset.                          | 15 Oct 2026, from the sample file. A true UTC field in export v2 would replace this (Q1).                                  |
| T6  | Raw data         | **The raw JSON of every activity is stored next to the normalised fields**, so later sprints can extract more without re-importing. Large per-second streams go to Supabase Storage, not the database. | Streams depend on Q1.                                                                                                      |
| T7  | Supabase env in Vercel | **The build accepts the env names synced by the Supabase integration for Vercel** (`NEXT_PUBLIC_SUPABASE_URL` / `SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` / `SUPABASE_PUBLISHABLE_KEY`) as fallbacks for `VITE_SUPABASE_URL` / `VITE_SUPABASE_PUBLISHABLE_KEY`; the `VITE_*` names win. Only these two public values are mapped, so synced secrets never reach the bundle. | 17 Oct 2026, PO request (automatic key sync as in an earlier project). Manual env vars stay possible (setup checklist §3.2). With two Supabase projects (T3), Preview may need the `VITE_*` override if the integration syncs one project to all environments. |
| T8  | Import save and outcomes | **One database function, `import_activities()`, saves a file in one transaction** (all-or-nothing per file) and gives every activity one outcome, checked in this order: *deleted earlier* (the row has `deleted_at`; not touched), *unchanged* (same data; also for activities that are not rides), *new* / *updated* (rides), *not a ride* (any other sport that was inserted or changed). With *skipped* from the client-side check, the six counts add up to the activities in the file, so importing a file again reports everything as unchanged. A file that is not a valid export is logged by `log_not_imported()` (P33). The whole file goes in one call, no chunking: the 305-activity sample is 0.5 MB and saves in 0.3 s; 3,050 activities (5.3 MB) save in under 1 s locally. Rides are the Strava types Ride, MountainBikeRide, GravelRide, EBikeRide, EMountainBikeRide, VirtualRide, Velomobile and Handcycle. | 18 Oct 2026, Sprint 1. Refines P13, P15, P17. Until export v2 is agreed (Q1), the optional fields `averageWatts`, `maxWatts`, `averageHeartrate`, `maxHeartrate` and `averageCadence` are read when present (provisional names); every other unknown field is kept in the raw JSON (T6). |
| T9  | Release data in the app | **What's new and What's next are generated at build time** by `scripts/build-release-data.mjs` from `CHANGELOG.md` and `docs/backlog.md` into gitignored JSON, regenerated before dev, build, lint, typecheck and tests. Labels (P18): Features → Feature; Bug Fixes and Performance → Fix; Reverts and Technical → Technical; release-please's "BREAKING CHANGES" notes are left out (the same commits are listed under their type). The backlog's sprint sections fail the build when broken. | 18 Oct 2026, Sprint 1. Committing the JSON was rejected: it goes stale when release-please updates `CHANGELOG.md`. |
| T10 | Re-import counts and duplicate IDs | **Only rides count as new, updated or unchanged; every activity that is not a ride is reported as "not a ride"**, also when it was already stored and did not change, so importing a file again reports the rides as unchanged and the rest as not a ride. **When the same activity ID appears twice in one file, the first one is imported and later copies are ignored** (not listed as skipped). Migration `20261028100000_import_not_a_ride_counts.sql` replaces `import_activities()`. | 28 Oct 2026, PO answers. Refines T8. |
| T11 | Start times (corrects T5) | **`startDateLocal` with a trailing `Z` is UTC** (it equals `start_time` in Strava's list; Strava's `start_date_local_raw` is 1–2 h later), so the import converts it to Brussels wall-clock time. Without a zone (export v2) it is already Brussels time. The first import after this fix reports existing rides as updated. | 28 Oct 2026, found while mapping the Strava list call. Supersedes the reading in T5. |
| T12 | Export v2 and streams | **The new Chrome extension writes export format v2** (`docs/export-format.md`): the activity list from `/athlete/training_activities` plus a GPX per ride for the route, power, heart rate and cadence (PO choice over Strava's internal streams call and the official API). **Per-second streams are stored per ride in a private Supabase Storage bucket**, not in the database row; the row keeps averages and maxima. One file per export, downloaded and imported as before (PO choice over pushing from the extension). | 28 Oct 2026, PO answers. Answers Q1. |
| T13 | Streams in Storage | **Bucket `streams` (private, gzip or JSON, 10 MB per file), one file per ride at `{auth.uid()}/{strava_id}.json.gz`**: the streams as canonical JSON (keys sorted), gzipped in the browser. Policies on `storage.objects` allow select, insert, update and delete only in the user's own folder. `activities.streams_sha256` (SHA-256 of the canonical JSON) and `streams_points` say what is stored: after `import_activities()` the app uploads only new or changed streams (4 at a time) for rides that are not deleted, so a re-import uploads nothing. A failed upload does not undo the import; "Try again" in a status card uploads only the failed rides from the file still in memory. `streams` is never in `raw`; invalid streams are dropped and counted, the ride still imports. Files up to 250 MB are read. The local Supabase now runs the Storage service (`supabase/config.toml`, `pnpm db:start`, CI). Migration `20261028120000_ride_streams_storage.sql`. | 28 Oct 2026, Sprint 2 Part C. Refines T6, T12. |
